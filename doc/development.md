# WizPlayer 開発計画

Androidを主対象とし、Windowsは動作確認に使う。

## 現在の実装

GBWizのGB/GBC実行部とAndroid・Windowsの画面を移植した。AndroidはアプリIDを `jp.wizplayer` とし、初回に選んだフォルダ内の `WizPlayer` に `rom`・`settings`・`state`・`save` を作る。

- Androidはarm64-v8a・x86_64向けデバッグAPKのビルドを確認。実機でGB外伝Iを起動し、通常セーブファイルとスロット1の作成、アプリ再起動後のフォルダ権限の復元とスロット1の読み込みを確認。通常セーブからのゲーム再開は未確認。
- Windowsはx64 Releaseをビルドし、GB外伝Iで180フレームの実行、映像出力、ステートの保存・復元を確認。画面操作・ショートカット・通常セーブは未確認。
- FC用binjnesはNesDQの `ccedbd0` を起点に取り込み、Wiiz由来のRAM・拡張ポート監視とNesDQのAPU監視を保持した。CRCによるカートリッジDB照会を削除し、iNES・NES 2.0ヘッダーを使う。ヘッダーで指定されたトレーナーは末尾の余剰データに左右されない。
- binjnesはAndroid arm64とWindows x64でビルド済み。Windows版ではROM選択にFCを追加し、ヘッダーでFCコアへ振り分ける。FCの通常セーブとスロット1は既存のWindowsデータフォルダ内の `FC` に保存する。
- Windows版の起動経路でFC対象7作品の600フレーム実行、映像出力、ステートの保存・復元を確認。FC版Wizardry Iで機能メニュー、マップ、アイテム画面の表示を確認。I〜IIIのマップデータは各10・6・6階分読み出し済み。座標移動とパーティー編成後のアイテム表示は未確認。アイテム画面はIDと状態の表示まで実装し、編集は未実装。
- Windows版のタイトルバー、メニューバー、機能メニューをFCとGB/GBCで共通化。ROMダイアログからGB外伝I、FC Wizardry I、GBC Wizardry Iへ切り替え、同じゲームウィンドウが使われることを確認。
- AndroidのROM選択は `.nes`・`.sfc`・`.smc` も表示する。FCはbinjnesで実行する。SFCのローカル確認用APKは、Androidディレクトリから `gradlew.bat assembleDebug -PwizplayerSnes9xSource=<Snes9xのソースフォルダ>` で作成する。SnesDQ5で使用するSnes9xリビジョン `1bcc369e89f08243e0a462882fb1f3e42e51de3a` を使用する。

- Androidの表示領域は縦向きで有効幅、横向きで有効高さを基準にする。SFC版DQ Vの実機画面で縦向きは幅1080 px、横向きはステータスバー下から画面下端までの高さ1011 pxを確認。

## ROM判定と保存

Wiiz・WiizV・NesDQにはSHA-256、SnesDQ5にはCRC32を使う箇所がある。作品判定、コア内部の補正、ステートの照合を調べてから移植する。セーブとステートはROM名を使い、同名ROMの保存先衝突を扱う。旧ステートの互換性は未確認。

Androidの既定ROMフォルダは `Documents/WizPlayer/rom`。設定・ステート・通常セーブには同階層の `settings`・`state`・`save` を使う。フォルダへのアクセス権は再起動後に復元する。
